# Feed Dispatcher & Sync Tool

本项目是一套轻量、高效、低维护成本的个人日常数据流调度与同步工具。系统每天定时对候选数据源执行健康检查、权重匹配与存活复检，并原子更新对外提供固定的订阅数据通道。

---

## 一、核心特性与设计原则

- **完整源替换**：只完整采用选出的单一最优源，绝不跨源混剪拼接数据。
- **沿用存活源**：优先复检上期选出的源，只要数据源依然保持存活有效即继续沿用，避免客户端频繁重载；若上期为组播源，仍会向上探测更高档位是否出现更优组播源，有则平滑升级、无则安全沿用（可用 `selection.upgrade_probe` 关闭）。
- **原子替换**：采用写入临时文件后 rename 机制，彻底杜绝网络中断产生的半写入或空文件。
- **全失败兜底**：若某天远程数据源临时不可用，系统自动保留历史有效版本，并通过 Webhook 发出告警。
- **进程文件锁**：防止定时任务和手动触发并发竞争。
- **历史快照与回滚**：保留最近多次更新的历史快照，支持一键 CLI 回滚。
- **运行摘要**：每次运行推送企业微信卡片，包含命中档位、档位变化（升级 / 降级 / 同档位更换 / 维持）、频道数与订阅地址。
- **纯标准库零外部依赖**：仅使用 Node.js 核心模块，轻量安全，启动迅速。

---

## 二、调度策略与权重规则

系统严格执行多级权重梯队，从高到低逐档匹配：
- **Tier 1 ~ Tier 20**：按网络类型与地域延迟定义的不同优先级策略组（可在 config.json 中灵活自定义；运营商不限的档位只需配置 `province`）。

### 筛选短路与排序逻辑：
- **同档位排序**：更新时间降序 > 项目数降序 > 稳定标识升序。
- **高档优先**：一旦高优先级档位找到并验证通过有效源，立即停止后续低档位的所有网络请求与验证。

## 四、手动立即更新

在仓库置顶 Issue 下评论 `/update`，即可立即触发一次与每日任务完全相同的更新流程。

- 仅仓库所有者（owner）评论有效，其他账号或机器人评论会被忽略
- 同一时间只允许一次更新（工作流并发组 + 10 分钟冷却）
- 触发后仍按正常流程推送运行摘要卡片
- 手机端可直接用 GitHub App 打开该 Issue 评论，无需电脑
